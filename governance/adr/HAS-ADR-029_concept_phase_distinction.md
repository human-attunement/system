# ADR-029 Concept文書における位相（志向／観測／様式）の明示

## Status
Accepted

## Context

HAS の [Concept 文書](../../docs/02_concept.md)では、これまで

- 志向（Orientation）
- 観測・観察（Observation）
- 様式・モード（Mode / Pattern）

が同一文脈上で語られる箇所があり、  
読み手によってはそれらが **同列の選択肢**、あるいは  
**優劣・順序を持つ概念**として解釈される余地があった。

特に以下の誤読リスクが確認されていた。

- 「どれを選ぶべきか」という評価的読解
- 観察・調律・行為様式を手順や段階として読む理解
- HAS を状態遷移モデルや実践フローとして受け取る解釈

これらは HAS の設計意図  
「判断の前提条件を示すが、行為や選択を指示しない」  
という立場と齟齬を生む可能性がある。

## Problem

Concept 文書において、

- 志向・観測・様式が同一位相として読まれてしまう
- 位相の違いが暗黙の前提に依存している
- 読み手が概念の関係性を自動的に序列化してしまう

という構造的な読み取りリスクをどう扱うか。

## Forces

- 概念を増やさずに誤読を防ぎたい
- 説明を厚くすると規範性が立ち上がる
- 図やモデルに頼らず、文章だけで成立させたい
- Kernel の意味内容は変更しない
- 将来の拡張時にも耐える概念構造が必要

## Decision
Concept 文書において、

- 志向（Orientation）
- 観測・観察（Observation）
- 様式・モード（Mode）

は**異なる位相（レイヤー）に属する概念**であることを明示する文章を追加した。

これにより、

- 横並びの比較対象ではないこと
- 優劣・順序・段階を示すものではないこと
- 判断前提の異なる層を記述していること

を、定義や手順を追加せずに示した。

## Rationale
- 位相の違いを明示することで、評価的・方法論的読解を防げるため
- 「どれを選ぶか」という問いを立ち上げないため
- HAS を操作体系ではなく、記述体系として保つため
- 将来、概念が追加されても同一原則で整理できるため

## Pros & Cons
- + 読み手が概念を序列化しにくくなる
- + Concept 文書の構造が安定する
- + 図示や補助資料に依存しない理解が可能
- − 抽象度が上がり、初読では把握しづらい可能性
- − 明確な「使い方」を求める読者には不親切

## Note
本変更は新しい概念を導入するものではない。

既存概念の**関係性の読み方**を固定するための、
構造的な補足である。

## Alternatives Considered
- 各概念に詳細な定義や注意書きを追加する  
  - 不採用理由：規範的・説明過多になる
- 図やマップでのみ位相を示す  
  - 不採用理由：文章単体で意味が完結しない
- 誤読は読み手に委ねる  
  - 不採用理由：再発可能性が高い

## Consequences
- Concept 文書は位相分離を前提に読まれる
- 今後の概念追加・修正時の整理軸が明確になる
- HAS が方法論として読まれるリスクが低減する

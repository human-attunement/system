# ADR-028 チェックリストに基づくコア文書表現の整理

## Status
Accepted

## Context
HAS のコア文書群は、段階的な追記・修正を経て拡張されてきた。

その過程で、以下のようなリスクが顕在化していた。

- 行為・推奨・目的が含意されているように読める表現
- 「望ましい状態」「正しい使い方」が存在するかのような誤読
- 判断・介入を促す文脈への回収可能性
- 同一概念の表現揺れによる読み手の解釈負荷

HAS の設計原則である  
「選択肢を狭めない」「判断を固定しない」  
という立場を維持するため、  
文書全体を **チェックリストに基づいて再点検**し、  
表現を整理する必要が生じた。

## Problem
既存のコア文書について、

- 行為・目的・推奨として読める箇所が残っていないか
- 判断を閉じる前提条件が暗黙に入り込んでいないか
- HAS を「使う方法論」として誤読させる余地がないか
- 文書間で立場や用語が一貫しているか

を体系的に確認し、  
必要な修正を一括して反映する必要があった。

## Forces
- 表現のわずかな差異が、規範的読解を生む
- 文書量の増加により、局所最適な修正では追跡不能
- 「誤解されないように説明する」こと自体が過剰防衛になりうる
- Kernel の意味内容は変更したくない
- 将来の自分が再読したときに迷わないことが重要

## Decision
チェックリストを作成し、  
**FAQ を除くすべてのコア文書**について、以下を実施した。

- 行為・推奨・目的を含意する表現の削除または書き換え
- 「参照される」「場合がある」等の冗長・防衛的表現の整理
- 状態・位置・判断前提に関する表現の一貫化
- 「示す／置いておく」という立場への統一
- HAS 内／外の切り分けを、評価ではなく記述として整理

Kernel の文言および意味内容は変更せず、  
**外側の文書を Kernel に整合させる方向で修正**を行った。

また、docs/08_failure_modes.md は、内容を踏まえて、[resources配下](../../resources/has_failure_modes.md)に移動した。

[FAQ](../../docs/06_faq.md)については、内容の変更度合いを考慮し、本ADRの変更とは別に実施することとした。

## Rationale
- HAS は行為体系ではなく、判断前提の整理であるため
- 表現が行為的になると、Doing World に回収されやすいため
- 読み手の理解を誘導しないためには、選択肢を並べる必要があるため
- 「正しく伝える」より「誤って閉じない」ことを優先するため

## Pros & Cons
- \+ 文書全体の立場が明確になった
- \+ 規範的・操作的な誤読の余地が減少した
- \+ Kernel との整合性が可視化された
- − 一部表現が抽象的に感じられる可能性
- − 即効性のある「答え」を期待する読者には不親切

## Note
本変更は内容の追加ではなく、  
**意味の射程を狭めないための整理**である。

何をすべきかは示さない。  
何が前提から外れやすいかだけを示す。

## Alternatives Considered
- 個別文書ごとに段階的修正を行う  
  - 不採用理由：全体の一貫性を保てない
- FAQ を含めた全面同時改定  
  - 不採用理由：FAQ は性質が異なるため分離が妥当
- Kernel 自体を修正する  
  - 不採用理由：Kernel の意味内容は既に十分に明確

## Consequences
- コア文書群は「行為を示さない」立場で統一される
- HAS を方法論として誤読するリスクが低減する
- 今後の追記・修正は、このチェックリストを基準に行われる
